# 领域资料

## 背景与目标

西宁非遗馆交流活动后，同一段银铜器演示视频被两家媒体分别上传：一家取得报道许可，另一家误把“现场可拍摄”当作“可公开完整工序与参与者肖像”。本系统把非遗项目、传承人允许展示的范围、体验场次、材料包、口译修订、青年作品与媒体用途建立成可追查关系，并在许可到期或撤回时给出下线清单、阻止继续分发。

## 基础约定

- 外部主体一律使用不含真实身份信息的引用编号（`*_ref`）。
- 交换时间采用带偏移量的 ISO 8601 字符串；无时区偏移的时间一律拒绝。
- 原始材料不入库，只保存受控引用（`source_ref`、`translation_ref`）或 64 位十六进制 `sha256` 摘要。
- 字段名称以 `contracts/entities.json` 为稳定接口约定；运行时数据文件位置由 `DATABASE_PATH` 决定。

## 展示范围（scope）

| scope | 含义 | 成立条件 |
| --- | --- | --- |
| `event-report` | 活动新闻报道 | 传承人同意包含该范围 + 机构持有当前有效许可 |
| `full-process` | 完整工序公开 | 传承人同意包含该范围 + 当前有效许可；关键工序默认不授 |
| `portrait` | 参与者肖像 | 素材中**每个**可识别参与者均肖像同意 + 当前有效许可 |
| `internal-archive` | 馆内存档 | 无需对外同意，但永不允许公开发布 |

## 核心业务规则

1. **重复影像是同一素材。** 素材以 `fingerprint_sha256` 全局唯一约束去重；任一机构再次上传相同指纹，只新增一条 `media_captures` 上传记录，返回原 `asset_ref`（`deduped=true`）。许可挂在素材上，不挂在上传记录上——第二家媒体不能借“自己上传的副本”获得许可。
2. **许可授予即核验基础。** 授予非存档许可时，系统即时核验传承人展示范围与参与者肖像同意；基础不成立则许可无法建立（HTTP 422），不留下“形式上有效”的许可。
3. **关键工序只公开摘要。** `is_key_process=true` 的工序文档，公众视图只返回 `public_summary`，原文/译文受控引用与指纹不出现在任何公众响应中；馆员侧可见完整修订链。
4. **原文与译文改动保持对应。** 工序文档按序号（`seq`）修订，每次原文修订必须同时携带至少一份同 `seq` 译文，否则拒绝登记。
5. **分发闸门。** 报道发布、展项上线前逐条核验所需范围：缺少当前有效许可（含到期）、传承人未同意或已撤回、参与者肖像同意缺失，均被阻止（HTTP 409）并写入审计。
6. **撤回/到期级联下线。** 许可撤回、到期或同意撤回后，`/staff/takedowns` 列出所有失去覆盖且仍在线的报道与展项；撤回许可会立即执行下线。下线项保留编号、下线时间与原因。
7. **活动发生过的事实不消失。** 场次、参与者、上传记录、审计事件只追加；撤回许可不会删除场次事实，公众仍可看到“活动已举办”的说明，但看不到体验者身份。
8. **公众只接触获准说明。** `/public/*` 只返回：项目摘要、场次事实（不含体验者）、当前在线且合规的报道、获准作品与素材、关键工序摘要。
9. **馆员从任一素材可查清全貌。** `/staff/trace/{asset_ref|指纹|work_ref|doc_ref|session_ref|material_kit_ref}` 返回关联的项目、场次、体验者、传承人及其当前同意边界、材料包、作品、文档修订、全部上传方、全部许可（含已撤回）与报道/展项状态。

## 事件留痕

`audit_events` 记录登记、授予、拒绝（`*.blocked`）、撤回、下线、去重等全部动作，可经 `/staff/audit` 回溯“谁在何时对哪个素材做了什么、为何被拦截”。

## 示例

`fixtures/example.json` 是不含真实身份的西宁银铜器场景：西宁广电持有 `event-report` 许可并发布报道；某自媒体的 `full-process` 授权请求与越界报道在种子加载时即被真实拦截；`make seed`（可加 `--reset`）载入。
